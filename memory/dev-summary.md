# 开发交互摘要（2026-06-06）

## 1. 新增 RSS 数据源

**问题：** 目前只从网页渠道爬取，想增加 RSS 订阅源方式获取资讯。

**关键分析：**
- 现有架构中 `crawl_channels()` 只处理 HTML 网页，需要新增 RSS 抓取通道
- 需复用现有分类器、存储、报告生成体系，最小侵入
- RSS 内容结构化程度高（标题/时间/摘要/图片字段清晰），解析比 HTML 简单

**实现效果：**
- `services.py` 新增 `crawl_rss_feeds()` 及辅助函数，使用 `feedparser` 解析 RSS/Atom
- 配置模型新增 `rss_sources` 字段，与 `channels` 平行存储
- 前端配置面板增加 RSS 源文本区，抓取结果中 RSS 文章带橙色标签
- 默认 RSS 源：`https://www.autonews.com/arc/outboundfeeds/rss/`

---

## 2. AV_Feeds.opml 订阅清单 + RSS 独立关键词

**问题：** RSS 源是专项内容，不应受通用搜索关键词约束；需要一个 OPML 订阅清单文件来管理 RSS 源。

**关键分析：**
- RSS 和网页搜索是不同性质的内容源，过滤条件应分离
- OPML 是 RSS 订阅列表的标准格式，支持嵌套分组

**实现效果：**
- 创建 `AV_Feeds.opml`（20 个自动驾驶相关 RSS 源）
- 新增 `rss_keywords` 独立配置字段（默认 `["autonomous", "self-driving"]`），RSS 内容只受此关键词过滤，不受通用 `keywords` 影响
- 前端增加 RSS 关键词文本区和「从 AV_Feeds.opml 导入」按钮
- `parse_opml()` 解析 OPML 文件，`POST /api/rss/import-opml` 导入到配置

---

## 3. 移除 RSS 关键词过滤 + 补充英文分类词

**问题：** RSS 源不需要关键词过滤（信任源内容）；同时英文 RSS 文章无法被中文分类关键词命中，需要补充英文分类词。

**关键分析：**
- RSS 内容本来就有针对性，再过滤会丢失有价值信息
- 分类器基于子串匹配，加英文词无需改算法

**实现效果：**
- 全局删除 `rss_keywords` 字段及相关过滤逻辑（storage/services/app/html/js 共 7 处）
- 5 大板块分类增加英文关键词（如 `regulation/launch/LiDAR/tender/analysis` 等 80+ 词）
- 英文文章分类测试全部通过（NHTSA→政策动态、Waymo→企业落地、LiDAR→技术动态等）
- `data/config.json` 自动合并迁移，旧配置不受影响

**实现效果：**
- 标签名变更：`关键词列表` → `渠道抓取关键词列表`
- 页面元素顺序调整：RSS 订阅源提到分类关键词之前

## 5. 全局 UI 重构（科技感 + 逻辑分组）

**问题：** 页面缺乏科技感和功能分区，所有内容平铺在一个面板。

**关键分析：**
- 采用深色主题 + 玻璃拟态（glassmorphism），视觉聚焦
- 5 个功能板块按职责重新分组

**实现效果：**
- 完整重写 `style.css`（深蓝渐变背景、毛玻璃卡片、青色发光强调色）
- 页面分为 5 个逻辑区：内容源设置 / 配置与分类 / 抓取与验证 / 内容管理 / 导出与发布
- 新增 `.glass`、`.action-bar`、`.btn-primary/secondary`、`.btn-wechat` 等样式系统

---

## 6. 标签页导航 + 分页搜索

**问题：** 内容管理区域太长（数百条资讯），导出与发布需要翻到底部才能看到，操作不便。

**关键分析：**
- 标签页可根治滚动问题，让各功能区域独立呈现
- 前端分页 + 搜索无需改后端，加载全量数据后在前端过滤/切片即可

**实现效果：**
- 页面顶部增加 5 个标签导航（内容源设置 / 配置分类 / 抓取验证 / 内容管理 / 导出发布）
- 资讯列表每页 20 条，底部显示页码导航（`‹ 上一页  1 2 3 … 7  下一页 ›`）
- 列表右上角增加搜索输入框（250ms 防抖，匹配标题/来源/内容/分类）
- 抓取后自动重置搜索条件和页码
